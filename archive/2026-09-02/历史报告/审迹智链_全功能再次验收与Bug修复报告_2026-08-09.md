## 2. 本轮实际修复

### 2.1 跨实例 RAG 快照

- Supabase 模式下，web 不再因为本机存在同名旧索引就直接读取本地 SQLite。
- 只有本地状态与远端活动状态的 `rag_snapshot_id`、`index_version`、`chunk_count`、案例 scope 全部一致时，才允许本地检索作为加速；否则使用远端活动快照。
- retrieval 日志使用实际执行检索的快照 ID，不再把远端新 ID 填入旧本地结果。
- 本地 manifest 与 Supabase 适配器使用同一规范化 chunk 摘要生成 `RAG-SNAPSHOT-*`，避免同内容在不同运行路径得到不同身份。

### 2.2 RAG staging 与 RPC 合同

- 新增 staging 异常、幂等重试和并发切换测试；中途失败不会把旧 active 集合改成残缺集合。
- 同一完整快照重试时保持幂等，不重复破坏现有 active 状态。
- 修正 `publish_rag_snapshot` 的 SQL grant/revoke 函数签名，避免 schema 中声明的权限签名与实际 RPC 参数不一致。

### 2.3 模型同意

- 后端按实际 case scope、provider、model_id、transmission_scope 和有效期精确匹配同意记录。
- 过期同意可以按同一合同续期，不会因活跃唯一键残留而无法再次确认。
- 前端保留服务端返回合同的回传路径，并拒绝把任意客户端 provider/model 伪装成已授权模型。
- 离线测试覆盖有效合同、provider/model/scope 错配、旧占位符归一化以及过期续期。

### 2.4 租户、任务和运行恢复

- 租户私有同名案例的本地临时物化路径按租户 hash 隔离，不能被公开或另一租户的同名案例遮蔽。
- run、review、cache、retrieval、RAG 查询携带显式 owner/scope；公共案例的基础证据与租户 overlay 分开。
- worker lease token 贯穿 heartbeat、complete、fail 和持久化 guard；失租后不继续高成本阶段。
- pipeline task 的 checkpoint、CAS、attempt 上限、成员复核和 crash-after-persist 合同已纳入专项回归。

### 2.5 前端深链接

初始化时原先先执行 `history.replaceState`，会把新打开页面 URL 中的 `?run=` 清掉，导致运行深链接无法恢复。本轮把 URL 规范化放到 run/task 恢复之后，刷新和直接打开运行 URL 均可恢复上下文。
