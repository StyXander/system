# 审迹智链 · 三套工作台结构方案

> 定位：会计师事务所审计项目组 · 业务承接 / 续聘复核 / 审计计划 · 收入风险预筛  
> 不是投资分析产品。不认定舞弊、不形成审计意见、不提供投资建议。  
> 计算逻辑与 `prototype/app.js` 口径一致，**未改公式、未自定风险阈值**。

## 如何打开

分别双击：

| 方案 | 路径 |
|---|---|
| A 专业审计工作台 | `A_专业审计工作台/index.html` |
| B 克制金融科技 | `B_克制金融科技/index.html` |
| C 证据链风险路径 | `C_证据链风险路径/index.html` |

每套均为自包含 `index.html + styles.css + app.js`，可整夹下载。

## 结构差异（重点：不是配色差异）

### A · 专业审计工作台

**信息架构**

- **顶栏**：工作底稿台品牌 + 项目/场景/截止日 engagement 条 + 系统状态。
- **左树导航**：01–05 固定工作区（项目 → 资料台账 → 矩阵总览 → 任务卡下钻 → 确认导出）。
- **中栏工作底稿**：高密度表单/表格/矩阵，像审计软件主编辑区。
- **右检查器**：当前项目快照、禁止事项、操作路径说明。

**流程怎么变**

- 资料预检以**台账表 + 完整度检查条**为主，强调“录数 → 定位 → 状态 → 保存”。
- 风险总览独立成页：四维矩阵用**工作底稿表**呈现（可得/部分/不可评价/校验失败）。
- 风险卡用 **Tab 下钻**（现象 / 公式 / 原文 / 缺口 / 正常解释）。
- 人工确认与导出在终点页，带**导出闸门**文案。

**适合**：演示“像事务所作业系统”的专业感与底稿 denseness。

---

### B · 克制金融科技

**信息架构**

- **顶栏极简** + **五步 Stepper**（全局唯一主导航）。
- **单列主内容**（项目页才有右侧 snapshot）。
- **底部固定操作坞**（复制文件名 / 保存复核 / 保存计算 / 导出）——操作路径始终可见。

**流程怎么变**

- 用 progressive disclosure：一次只强调当前一步。
- 资料预检用 **四拍流程胶囊**（录数→定位→检查→保存）降低“大表压迫感”，但字段完整保留。
- 矩阵是 **2×N 模块栅格**，不是大表；KPI 三指标紧跟其后。
- 风险下钻仍为 tabs，但视觉更轻。
- 确认与导出依赖底栏主按钮，符合产品化工作流。

**适合**：路演时强调“好用、克制、现代 SaaS”，避免审计软件陈旧感。

---

### C · 证据链与风险路径

**信息架构**

- **顶部路径板**（项目边界 → 证据接入 → 确定性计算 → 四维交叉 → 风险卡 → 人工闸门）是第一视觉中心。
- **左证据链**纵向节点；**右详情区**随节点切换。
- 风险卡下钻改为 **左侧序号链 + 右侧内容**（强调路径，而不是横向 Tab 工具栏）。

**流程怎么变**

- 用户先看见“证据如何变成线索”的链路，再进入表单。
- 矩阵做成 **路径节点表**（维度 / 状态 / 在路径中的位置）。
- 明确系统状态条：空白 / 资料不全 / 校验失败 / 缓存回放 / 可复核。
- 导出仍在路径终点，与人工闸门绑定。

**适合**：答辩时讲清“可追溯、可反证、有缺口”的产品叙事。

## 三套共同能力

1. **全部业务字段**：公司、截止日、场景、行业、本年/上年、金额单位；四项金额与五项来源定位。  
2. **确定性计算**：收入增长率、应收增长率、差额（百分点）；上年为 0 或非法数字 → 校验失败。  
3. **来源准入**：四行完整才生成候选风险卡。  
4. **四维矩阵状态**：财务/业务/行业/叙述 + 来源约束；后三维首版诚实标“不可评价”。  
5. **下钻**：现象、公式展开式、原文依据、资料缺口、正常解释；审计计划场景显示认定/程序。  
6. **人工复核**：未复核 / 保留 / 降级 / 暂缓 + 说明。  
7. **导出**：复核闸门通过后下载本地 `.txt` 草稿（非正式报告）。  
8. **系统状态**：空白、资料不全、来源缺口、校验失败、缓存回放、可复核、已记录复核。  
9. **适配**：约 1440px 桌面布局；约 375px 单列重排。

## 明确未做（避免越界）

- 未接大模型、未冻结正式案例、未设 R1 阈值、未输出舞弊结论或投资建议。  
- 业务规模 / 行业 / 叙述维度仅占位，等待规则与资料接入。  
- 导出不是监管口径的审计报告。
