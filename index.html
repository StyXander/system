                    技术说明

                    三 Agent 固定分工

                    • 质疑角色：按专业规则提出需要进一步了解的情况，并标明资料依据；不猜测动机、不下舞弊结论。
                    • 反证角色：寻找正常解释、相反资料和缺失资料；找不到也会写明，不为凑答案补造事实。
                    • 语义复核角色：检查措辞能否被资料支持，必要时保留、降级或暂缓；不跳过程序校验。

                    案例隔离 RAG

                    每个案例独立建立索引，公司、case_id 与 T0 在服务端硬过滤；检索只作为候选原文，须回到原件复核。

                    推荐技术栈对应（实际实现）

                    竞赛附件列出的是可选技术方案。系统按所需能力选型并保留可复验边界，不为凑框架名称虚报未使用组件。

                    LLM正在读取模型通道。中文审计语境的结构化工具调用；失败码与 Token 用量随运行留痕。
                    Agent 编排自研有界状态机 · Challenge → Counter → Review支持协作、反证和逐角色硬校验，不声称使用 Anthropic SDK 或 AutoGen。
                    RAG / 向量案例隔离 RAG · FAISS + SQLite + NumPy确定性字元 n-gram 向量，来源指纹、固定问题集与证据 ID 绑定；未使用 LangChain、LlamaIndex、ChromaDB 或 Milvus。
                    Web / 前端FastAPI + Uvicorn · 原生 HTML / CSS / JavaScriptAPI 路由与自动 OpenAPI 文档；前端采用单一演示状态机和响应式交互。
                    PDF / 数据处理PyMuPDF · NumPy完成公开年报文本提取、页码定位、确定性计算与向量处理；未使用的 pandas / pdfplumber 不列入。

                    AI 边界

                    • 不做舞弊认定，只输出待核查风险线索。
                    • 不出审计意见，不替代函证、检查、访谈等程序。
                    • 不给投资建议，不做估值判断。
                    • 关键专业判断、案例选定与最终发布由人决定。
