# 审迹智链（AuditTrace）四人团队职责分工书

> **版本：** V3.1（对齐《详细项目计划书》V2.3 交互能力修订版）  
> **日期：** 2026-07-19  
> **团队：** 4 人（队长、队员 A、队员 B、队员 C）  
> **对齐依据：** `05_审迹智链_详细项目计划书_V2_审计师定位修订版`（当前正文为 V2.3）第十四、十五章及 §8.1.1、§8.1.2、§9.2、§10  
> **用途：** 组内执行与老师审阅；不设置固定周报、每周录屏、每周新增规则数量等管理性交付  

**相对 V3.0 的主要变化（对齐计划书 V2.3）：**  
- 增加 **风险指标用户自选**：界面展示多指标（映射 R1—R8），用户勾选本次分析/导出范围；禁止自创舞弊评分；  
- 增加 **补充资料续分析窗口**（条件项）：取得待索取/补充资料后绑定风险卡并局部重跑，不是开放式闲聊；  
- 阶段门：W4 验收指标勾选；W6 可做窗口线框；W7 核心链稳定才接真上传与局部重跑；  
- 仍为拟实现设计，**不等于已上线**。

**相对 V2.0（老师意见修订版）的主要变化（沿用）：**  
- 用户定位改为**仅事务所审计项目组**（承接 / 续聘 / 计划），删除投资者模式表述；  
- 产品输出改为**预审风险备忘录、Top 5 待核查事项、资料依据缺口与待索取资料**，禁止舞弊认定与审计意见；  
- 技术主线改为**确定性计算 + 质疑/反证/语义复核固定角色 + 程序硬门槛**；Coze 仅作可选试验，不以 Coze 为主交付；  
- 规则优先级改为 **R1/R2 先跑通**，R3—R8 候选、按阶段门接入；  
- 周计划改为 **W1—W10 阶段门（G0—G9）**，与最终计划书日历映射一致；  
- 删除“覆盖率 70%”“源页准确率 75%”等**未经验证的效果目标**，指标只保留计划书中的工程验收口径（拟冻结，非当前成绩）。

## 一、项目一句话与边界（全员统一）

> **审迹智链面向事务所审计项目组，用公开资料交叉验证收入风险，输出可追溯待核查线索、资料依据缺口和待索取资料。**

| 项目 | 统一口径 |
|---|---|
| 核心用户 | 会计师事务所审计项目组（项目合伙人、项目经理、初步风险评估人员） |
| 三个场景 | 新客户业务承接、续聘复核、审计计划 |
| 首版主题 | 收入确认 + 销售与收款循环 |
| 首版输入 | 截止分析日（T0）前已公开的年报、公告、审计报告、监管信息、同行与公开行业资料 |
| 可选补充 | 授权脱敏后，经**续分析窗口**绑定指定风险卡后局部重跑（条件项，核心链稳定后） |
| 风险指标 | 映射已实现规则 R1—R8；用户可勾选本次分析/导出范围，禁止自创舞弊评分 |
| 目标输出 | 预审风险备忘录、最多 5 项待核查事项、待索取资料清单；仅**审计计划**场景可显示候选管理层认定与建议程序 |
| 明确不做 | 投资建议、完整审计平台、舞弊认定、审计意见、自动承接/续聘决定；开放式闲聊客服 |
| 最小可演示闭环 | 1 个开发/演示案例 × R1 × 人工结构化录入 → 确定性计算 → 质疑/反证/复核 → 引用与公式硬校验 → 人工确认 → 1 张风险卡草稿及待索取资料（指标自选与续分析窗口不进入最小闭环必做项） |

**全员禁止：** 把“拟/候选”写成“已实现/已验证”；补造页码、数字、案例或实验结果；在未授权时读取或使用 T1 后验材料调规则。

## 四、各角色详细职责

### 4.1 队长：工作流与系统整合

**负责：**

1. 搭建并维护 Web 原型（当前可为静态页 / Streamlit 等；以能本地打开、可验收为准）；  
2. 实现**确定性计算**（增长率、差额等由程序复算，模型不得改写公式结果）；  
3. 固化质疑 → 反证 → 语义复核的**固定一轮流程**（非自由辩论）；  
4. 实现证据硬门槛：Schema、证据 ID、T0 日期、原文、公式、字段、禁用词；  
5. 实现**风险指标勾选状态机**（已实现规则可勾选、候选灰显；勾选集合决定运行与导出范围）；  
6. （条件项）实现**补充资料续分析窗口**：关联风险卡、模板/粘贴预检、授权脱敏确认、**仅局部重跑**绑定卡；  
7. 管理版本、密钥、经核验缓存、实时/缓存标识与三级演示降级；  
8. 按阶段门做集成：每周期形成**可运行版本或可复现失败**；核心链路未通过时不扩功能（尤其不抢做续分析窗口）。

**不负责 / 不做：**

- 代替 A 撰写专业规则或认定口径；  
- 代替 B 从原件抄录未核验数字；  
- 在缺证据时用模型补造页码或结论；  
- 把续分析窗口做成无绑定对象的开放聊天。

**常用工具（建议，非强制）：** Trae / Codex / Cursor 等 Vibe Coding；本地 Python/HTML 栈。  
**变更记录：** 只对影响规则、数据口径、模型/提示词、关键代码或验收结果的变更写简要日志（日期、变更项、版本、人工修改、验证结果、未决问题）。

### 4.2 队员 A：审计逻辑与专业规则

**负责：**

1. 梳理销售与收款循环节点与“异常信号—风险机理—资料缺口—场景化后续动作”映射；  
2. **优先**完成 R1（及随后 R2）规则卡：所需字段、公式、正常解释、资料缺口、待索取资料、计划场景候选认定与建议程序；  
3. 为每条规则提供**界面用指标显示名、一句话释义、默认是否建议勾选、资料不足时是否灰显**；  
4. 明确补充资料进入后，对该卡风险假设 / 正常解释 / 资料缺口应如何更新（仍禁止自动舞弊认定）；  
5. R3—R8 只作为**候选规则库**维护；资料不可得或挤占主链路时**不强制工程化**，界面保持候选灰显；  
6. 复核系统输出措辞：不得出现舞弊认定、审计意见、投资建议等禁用表述；  
7. 在 B 提供数字后，组织或完成公式人工复算对照。

**R1 最小口径（与计划书一致）：**

- 收入增长率＝（本年收入－上年收入）÷上年收入；  
- 应收账款增长率＝（本年应收－上年应收）÷上年应收；  
- “高出多少才提醒”**不得擅自定阈值**，写“阈值待样例测试后由团队确认”。

**交付形态：** 规则说明 Markdown/Word/Excel 择一；每条规则含版本状态（候选 / 可实现 / 已实现待验）及指标释义表字段。

### 4.3 队员 B：公开数据、同行与评估

**负责：**

1. 候选案例与年报的**可得性预检**（正式来源、公开日期、连续期间、字段与 PDF 可读性）；**预检时不读 T1**；  
2. 制作 DEV_T0 数据切片与**同一份来源台账**（文件名、披露日期、PDF 页码、印刷页码、原文位置、单位）；  
3. 同行对照：默认 3 家、最多 5 家，口径与期间须可比；  
4. 明确案例角色：**开发/演示** vs **有限留出**；按 B0 信号选中的案例必须标为开发/演示，不得再称留出；  
5. 为续分析窗口准备**脱敏模拟补充资料模板样例**（合同/销售明细/回款等摘要字段），并在台账中单独登记补充资料行；  
6. 正式 T0 仅在 Research Contract 冻结后形成；**接触 T1 后不得再改该案例 T0 规则、提示词或人工确认结果**（§12.4）。

**首周 / 最小数据底线：** 至少 4 个数字（本年/上年收入、本年/上年应收账款）+ 完整来源定位；找不到印刷页码写“原件未标注”，禁止猜测。补充模板样例不要求 W1 完成。

### 4.4 队员 C：产品表达与竞赛材料

**负责：**

1. 核心页面文案：项目设定、资料预检、风险总览/矩阵、风险卡下钻、人工确认与导出；  
2. **风险指标勾选区**文案：列表标题、勾选提示、“自选只决定分析范围，不改变证据门槛与人工确认”；  
3. **续分析窗口**文案：入口按钮、资料类型名、授权/脱敏勾选、预检失败提示、“仅用于缩小资料缺口，不形成审计结论”；  
4. 统一术语：待核查、资料依据、正常解释、资料缺口、待索取资料、风险指标、续分析；  
5. 界面固定提示：使用边界、来源台账说明、实时/缓存回放标识、免责声明；  
6. 初赛计划书排版与表达、5 分钟视频脚本/成片、PPT/展示材料（按主办方要求）；  
7. W6 起配合组织非项目成员形成性试用，根据真实反馈改文案与路径，**不要求每周完整设计稿或录屏**。

**不做：** 单独合规大表堆砌；在材料中写未验证准确率或“已发现舞弊”；暗示用户勾选等于系统已认定风险。

## 六、与最终计划书一致的“五页核心界面”分工

首版 5 个核心页面（计划书 §10），不以页面数量代替链路：

| 页面 | 主责内容 | 协作 |

## 七、AI 三类角色与人的边界（计划书 §8.2）

| 系统角色 | 只能做什么 | 不能做什么 | 人的对应 |
|---|---|---|---|
| 质疑 | 按规则提出风险假设并引用资料依据 | 无依据猜动机或认定舞弊 | A 定规则；队长实现 |
| 反证 | 找正常解释、相反资料、缺失项；找不到须明示 | 为凑字段编造事实 | A 定正常解释库；B 供公开资料 |
| 语义复核 | 检查措辞是否有依据，建议保留/降级/暂缓 | 绕过硬门槛批准导出 | **最终确认必须由人** |

程序硬门槛顺序（拟）：JSON/Schema → 证据 ID → T0 日期 → 原文反查 → 数字与公式 → 字段与禁用词 → **人工确认**。

## 八、验收用语与互查

1. **“已实现”** 须有代码与测试；**“已验证”** 须有冻结输入与验收记录。  
2. 任一风险卡导出前：来源定位与公式复算须可人工核对。  
3. 交叉检查建议：A 验公式与认定；B 验数字与页码；C 验页面文字是否越界；队长验运行与日志。  
4. 两个历史案例只说明方法与工程可行性，**不得宣传普适舞弊识别准确率**。
