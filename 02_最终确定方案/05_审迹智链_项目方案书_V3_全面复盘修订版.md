# 审迹智链（AuditTrace）项目方案书 V3

> **题目：** 审迹智链（AuditTrace）——面向审计前置阶段的证据约束型收入风险预筛查多智能体  
> **竞赛：** 北京市大学生数智会计创新应用竞赛  
> **版本：** V3.0·全面复盘修订版  
> **日期：** 2026 年 7 月 24 日  
> **使用方式：** 本文是面向评委、视频和答辩的方案主稿；`V2.4.4`保留为团队内部工程执行底稿。  
> **项目边界：** 系统输出待核查线索、正常解释、资料缺口和待索取资料；不认定舞弊、不出具审计意见、不提供投资建议。

## 一、项目概述

### 1.1 要解决的真实问题

会计师事务所在新客户承接、续聘复核和审计计划阶段，通常需要在时间有限、公开资料分散的情况下，先判断收入及销售收款循环中哪些事项值得投入进一步程序。年报中的收入、应收、现金流、客户和管理层表述可以提供线索，但这些数字、文本和来源页面分散在不同章节；传统人工预检效率低，而通用大模型又容易跳过来源、补写事实或把线索说成结论。

审迹智链面向审计项目组，将公开披露资料整理为可回查字段和页级片段，先由程序完成计算与来源校验，再让固定分工的智能体提出、反证和复核线索。每一项输出都保留“为什么值得问、有哪些正常解释、还缺哪些资料、原始出处在哪里”。

### 1.2 一句话定位

**审迹智链帮助审计项目组在承接、续聘和计划阶段，从公开资料中形成可回查的收入风险预筛线索与资料索取清单。**

### 1.3 目标用户、场景和输出

| 场景 | 使用者的核心问题 | 系统输出 | 人工必须决定的事项 |
|---|---|---|---|
| 新客户承接 | 是否存在需要进一步了解的收入、回款或披露异常线索 | 待核查事项、公开资料缺口、待索取资料 | 是否承接、是否追加尽调程序 |
| 续聘复核 | 相较上一期是否出现值得重新评估的变化 | 期间变化、正常解释、拟补充资料 | 是否续聘及风险应对策略 |
| 审计计划 | 销售与收款循环应优先关注哪些认定和资料 | 风险卡草稿、认定映射、建议程序 | 重要性、风险评估和审计方案 |
| 取得补充资料后 | 原待索取资料是否足以缩小或澄清线索 | 绑定风险卡的续分析草稿、更新后的缺口与待索取清单 | 授权/脱敏、是否保留线索、后续程序 |

系统不替代函证、检查、访谈、穿行测试或职业判断。公开资料只用于前置筛查；任何内部资料都须经授权、脱敏和人工关联后才能进入续分析。

**团队确认（2026-07-24）：补充资料续分析窗口为正式交付目标，不再作为“可不做”的可选砍项。** 在公开资料主链（R1/R2、来源闸门、三Agent与硬校验）通过后按期实现；在实现前，页面与材料必须标注“尚未接入”，不得用静态示意冒充可上传续跑。

## 二、专业基础与规则设计

### 2.1 准则依据与系统对应

本项目不是把会计准则改写成一组“舞弊分数”。规则只负责筛出值得进一步了解的线索，并映射到审计风险评估、相关认定和后续资料。

| 准则或依据 | 核心要求 | 在审迹智链中的对应 |
|---|---|---|
| 《中国注册会计师审计准则第1211号——重大错报风险的识别和评估》第1、6—9、17条 | 识别和评估财务报表层次及认定层次的重大错报风险；相关认定、风险评估程序和后续应对相衔接 | 规则卡以交易、账户余额和披露为入口，输出相关认定、资料缺口和建议进一步程序，而不替代风险评估结论 |
| 第1211号第10—12条 | 固有风险因素包括复杂性、主观性、变化和不确定性；特别风险由注册会计师判断 | 把跨期波动、现金流背离、业务模式变化等作为“需解释因素”，不自动标为特别风险 |
| 《企业会计准则第14号——收入》第4条 | 在履行履约义务、客户取得商品控制权时确认收入 | R5、R7关注收入政策、控制权证据与披露表述是否需要补充核验 |
| 《企业会计准则第14号——收入》第11—13条 | 区分时段与时点履约；判断控制权转移的迹象 | 对工程、发货验收、期末交易等场景索取合同、验收、控制权转移和期后结算资料 |
| 《企业会计准则第14号——收入》第34条 | 按转让前是否控制商品判断主要责任人与代理人，决定总额或净额确认 | R5把控制权、主要责任、存货风险和定价权列为核查问题，而非直接根据收入规模下结论 |

### 2.2 销售与收款循环的规则库

| 规则 | 待识别线索 | 关联认定/判断 | 需要的资料或后续动作 | 当前状态 |
|---|---|---|---|---|
| R1 应收—收入背离 | 应收账款增速相对收入偏高 | 存在、计价、截止、收入真实性 | 账龄、期后回款、合同结算、客户明细 | **当前工程版可运行** |
| R2 收入—经营现金流背离 | 收入与经营现金流/收现质量需解释 | 收入确认、计价、商业合理性 | 销售收现、OCF、净利润、营运资本构成 | **专业规则 v0.2 已提交审查；当前工程仍为方向比较版，待对齐实现** |
| R3 产销量—收入不匹配 | 产能、产量、销量与收入趋势需解释 | 发生、完整性、截止 | 产销报表、发运、验收、业务统计 | 候选规则，待资料 |
| R4 客户集中度与交易特征变化 | 客户集中度或交易对手特征突变 | 存在、关联方、披露 | 前五大客户、合同、公开登记信息 | 候选规则，待资料 |
| R5 总额法/净额法依据 | 控制权判断与业务模式不一致 | 分类、列报、收入计量 | 合同、履约责任、定价权、存货风险 | 候选规则，待资料 |
| R6 毛利率逆行业变化 | 产品结构可比时毛利与行业显著背离 | 计价、披露、商业合理性 | 产品结构、成本、同行口径 | 候选规则，待资料 |
| R7 管理层表述与数字不一致 | 年报叙述与数据趋势相互矛盾 | 披露、完整性、一致性 | 管理层讨论、公告、业务说明 | 候选规则，待RAG语义检索 |
| R8 期末交易与期后回款线索 | 期末确认与后续结算需解释 | 截止、发生、计价 | 发货、验收、回款、退货资料 | 候选规则，待内部/公开资料 |

**规则状态说明：** R1 为当前开发样例可运行工程版。R2 已收到专业规则说明 v0.2（见 `04_第二周任务与成果/R2 收入现金质量核查规则 v2(1).docx`），但后端与网页仍按“收入正增长下的方向比较”工程版运行，**不得把 v0.2 全文写成已上线**。R3—R8 在资料、口径和专业复核未完成前，只作为规则库展示，不生成风险卡。

### 2.3 R2 的可比性保护与 v0.2 对齐方向

经营现金流为零、绝对值很小或跨期由正转负时，单纯同比百分比会产生数千个百分点的视觉失真。结合标准股份开发样例与 R2 规则 v0.2，R2 的实现与展示遵守：

1. 上年经营现金流为零、低于可比基数（v0.2 默认：上年 OCF 绝对值不足上年收入的 3%）、或本年与上年符号相反时，不显示“现金流增速”和“增速差额”；
2. 改为显示经营现金流金额变动、经营现金流/收入、净利润现金含量（净利润为正时）或方向组合描述，并标记“同比不宜比较，需人工解释”；
3. 趋势背离仅在可比前提下计算；v0.2 默认差值阈值为 20 个百分点，是否采用及行业适配由专业成员确认后写入版本参数；
4. 销售收现率、净利润现金含量等 v0.2 新增主指标，须在字段入台账、可回指且通过复算后，才进入触发与风险卡；
5. 阈值、基数标准与正常解释由审计专业成员确认并版本化保存；正常解释不得自动关闭线索。

这项保护来自对标准股份开发样例的核查：2024年经营现金流仅为正157.05万元，2025年变为负3,228.04万元。原始年报数据无误，但直接计算同比会产生不适于审计表达的−2,155.38%。

### 2.4 补充资料续分析窗口（已确认交付）

取得待索取或内部补充资料后，审计师通过**补充资料续分析窗口**把资料发回系统、绑定既有风险卡后继续分析。该能力已确认为竞赛交付目标，最低交互如下：

| 要点 | 口径 |
|---|---|
| 入口 | 风险卡草稿、资料缺口/待索取资料页的“取得补充资料后继续分析” |
| 用户动作 | 选择关联风险卡 → 选择资料类型 → 模板上传或结构化粘贴 → 确认授权与脱敏 → 提交继续分析 |
| 系统动作 | 预检公司/期间/单位/字段/授权 → 写入 evidence 与来源台账 → **仅局部重跑绑定卡**的质疑—反证—复核—硬校验 |
| 明确不做 | 开放式闲聊；未绑定风险卡的自由问答；因上传资料自动认定舞弊或绕过人工确认直接导出 |
| 当前状态 | **已确认要做，工程尚未接入**；主链稳定前可先交付线框与文案，但不得标为已运行 |

## 三、总体方案与多智能体架构

### 3.1 端到端工作流

```text
公开年报 / 已授权补充资料
        ↓ 资料预检：来源、期间、页码、T0、单位、字段完整性
确定性计算：R1/R2公式、可比性保护、规则状态
        ↓
RAG V1：仅从已确认资料召回带 evidence_id 的页级片段
        ↓
质疑Agent → 反证Agent → 语义复核Agent（Agent-as-a-Judge）
        ↓
程序硬校验：JSON、证据ID、禁用词、规则/公式/来源不可被改写
        ↓
人工确认：保留、降级或暂缓 → 待核查事项与待索取资料
```

### 3.2 三个角色的边界

| 角色 | 只做什么 | 输入 | 输出 | 不能做什么 |
|---|---|---|---|---|
| 质疑Agent | 基于触发规则提出待了解的风险假设 | 确定性结果、登记证据包、RAG片段 | `claims`、资料缺口、待索取资料 | 不能认定舞弊或改写数字、页码、规则结论 |
| 反证Agent | 主动找正常商业解释、相反材料和缺口 | 同一证据包及质疑结果 | 正常解释、反证不足说明、补充资料 | 不能新增外部事实或空泛“洗白” |
| 语义复核Agent | 检查前两步是否超出证据，建议保留、降级或暂缓 | 前两步结构化结果及证据包 | `retain` / `downgrade` / `defer` | 不能新造事实、替代人工审批 |

语义复核与 Agent-as-a-Judge 的思想一致：由独立角色评价前序输出是否符合规则和证据约束；但最终裁决仍由程序硬校验和审计人员完成。

### 3.3 模型与程序的分工

| 必须由程序完成 | 可由模型辅助完成 | 必须由人确认 |
|---|---|---|
| 数字计算、单位换算、来源字段、页码、披露日、T0过滤、R2可比性判断、Schema校验、证据ID校验、禁用词校验 | 文本线索归纳、正常解释、资料缺口表述、待索取资料初稿、前序输出的语义一致性检查 | 规则阈值、案例冻结、内部资料授权、是否保留线索、后续程序、对外表述 |

### 3.4 结构化输出与失败关闭

每次模型调用使用 `agent_output_v1`，至少记录 `run_id`、角色、规则ID、状态、主张、`evidence_id`、正常解释、资料缺口、待索取资料和理由。程序校验任何证据ID是否属于本次证据包；模型输出包含舞弊认定、审计意见、投资建议、无效JSON、越界引用或服务不可用时，立即停止后续角色，不生成伪造风险卡。

运行记录同时保存规则、参数、来源哈希、模型ID、提示词版本、输入/响应哈希、耗时和token。页面需要明确区分“真实运行”“缓存回放”“未配置/调用失败”；缓存不能冒充实时调用。

## 四、RAG V1：可回查的资料检索，而不是把年报全文交给模型

### 4.1 RAG 的范围

RAG V1 只处理已经确认来源、允许使用且满足分析时点的资料。它不搜索开放网页、不把模型记忆当来源，也不替代字段台账。首版数据范围为标准股份开发年报和后续经授权的第二案例资料。

### 4.2 RAG V1 的实现设计

| 环节 | 设计 | 必须留下的记录 |
|---|---|---|
| 入库 | PDF预检、文本抽取、页码与文件哈希登记 | `document_id`、文件名、披露日、T0、哈希、解析状态 |
| 切片 | 按页码、标题与段落切片，保留原文、页码、期间、资料类型、`evidence_id` | `chunk_id`、页码、标题、字符范围、来源ID |
| 索引 | SQLite保存元数据；FAISS保存向量；关键词与向量混合召回 | 索引版本、嵌入模型版本、构建时间 |
| 检索 | 先按公司、案例、T0、资料类型过滤，再召回；最多将6个片段送入模型 | `retrieval_run`：查询、过滤条件、候选数、排序、命中ID |
| 页面回查 | 风险卡可展开命中文段、来源和页码；无命中显示“资料不足” | 查询与展示记录 |

RAG V1 的验收不是“能回答问题”，而是固定问题集能验证三类结果：命中相关页、拦截T0后资料/其他公司资料、无命中时不补写。未通过这三项，页面不得显示“RAG已实现”。

## 五、五项核心创新

1. **四维交叉验证。** 财务数字、业务链条、行业参照和披露表述被统一映射到同一规则和来源台账，避免只看单一财务比率。
2. **从线索到资料缺口。** 每项候选不只给“异常”，还给正常解释、缺少资料和待索取项目，使输出能进入审计项目组的下一步工作。
3. **证据硬准入。** 来源、页码、披露日、T0、公式和单位由程序拦截；模型不能更改这些底座。
4. **强制反证与语义复核。** 固定“质疑—反证—复核”链，要求模型主动说明正常解释和证据不足，不让单向叙事直接进入风险卡。
5. **时点隔离与可复放。** 运行冻结资料、规则、模型、提示词与检索索引版本；在正式评估中通过T0/T1隔离减少后验信息污染。

创新不在于训练新的基础模型，而在于把大模型的开放式语言能力放入可验证、可追溯、可人工接管的审计预筛流程。

## 六、技术路线与当前原型状态

### 6.1 技术选型

根目录 `index.html` 保持为唯一展示页；FastAPI 负责密钥隔离、资料校验、确定性计算、智能体调用和运行留痕。前端不保存API Key。

项目不在首版引入 LangChain、AutoGen 等通用编排框架：三角色顺序固定、输入输出合同明确，直接实现可以更直观地审计调用、失败和版本。RAG V1使用 PyMuPDF/pdfplumber 进行解析，SQLite 与 FAISS 保存元数据和向量索引；pandas/numpy用于计算与测试。后续只有在分支、工具调用或任务编排确实增长时，才评估引入框架。

### 6.2 现有事实与目标状态

| 能力 | 截至V3的事实状态 | V3后的验收目标 |
|---|---|---|
| 主网页与本地后端 | 已有根目录网页、FastAPI启动脚本和R1/R2页面联动 | 稳定启动、页面与后端同口径 |
| 年报字段和来源 | 标准股份开发资料已登记，完成技术交叉核对；仍待专业人工复核 | 每个参与字段可回到文件、页码、期间与哈希 |
| R1/R2确定性计算 | R1/R2工程版已接入；R2专业规则 v0.2 已提交，工程尚未按 v0.2 全量实现 | R2 对齐 v0.2 的字段、可比性保护、阈值与失败样例；有人工复核记录 |
| 三Agent固定链 | 已写入固定流程、JSON和证据ID校验 | 保存至少一次真实完整运行与一次故意失败闭环 |

| 正式效果评估 | 尚未启动 | Research Contract冻结后再开展，不提前生成结论 |

## 七、验证方案：先验证可追溯性，再比较效果

### 7.1 运行前的确定性验收

| 指标 | 定义 | 可在开发样例阶段报告吗 |
|---|---|---|
| 字段来源回指完整率 | 有文件、披露日、页码、定位和`evidence_id`的参与字段数 / 参与字段总数 | 可以，需报告分子和分母 |
| 公式复算一致率 | 人工复算与程序结果一致的规则运行数 / 抽查运行数 | 可以，需保留复算记录 |

### 7.2 正式比较设计

| 组别 | 定义 | 用途 |
|---|---|---|
| B0 | 仅确定性规则与阈值，不调用模型 | 观察规则层的基础输出 |
| B1 | 通用模型直读固定资料，不使用RAG和硬校验 | 观察无约束模型的来源与表述问题 |
| B2 | RAG + 单Agent，不使用反证/复核链 | 观察检索与单角色的增益/局限 |
| B3 | 审迹智链完整流程：RAG + 三Agent + 硬校验 + 人工确认 | 评估完整约束流程 |

正式评价开始前必须冻结案例角色、分析时点T0、T1隔离方式、资料包、规则、阈值、模型、提示词、索引、预算和评价指标。两个案例最多支持有限的过程比较，不支持“普遍准确率”“显著优于所有模型”等外推结论。

## 十、伦理、合规与风险控制

1. **输出边界。** 固定展示“本结果由AI辅助生成，仅用于审计前置风险筛查；不构成舞弊认定、审计意见或投资建议”。
2. **资料边界。** 公开资料使用官方披露或经核验副本；内部资料仅在授权、脱敏、绑定风险卡后进入已确认交付的续分析窗口。
3. **模型边界。** 模型不可修改来源、数字、公式、页码和规则状态；无来源、无效JSON或越界引用必须失败关闭。
4. **时点边界。** 正式评估资料按T0/T1隔离；接触T1后不得回写规则、提示词或T0人工判断。
5. **人机边界。** 人决定规则、阈值、案例、风险保留、资料权限和对外表达；系统不代签、代批或自动出结论。

## 十一、V3 的成功标准

到初赛材料冻结时，团队至少应能展示一条完整且诚实的主链：一份已登记公开年报经过来源预检和R1/R2计算，RAG只回传带页码的片段，三Agent输出通过结构化与证据ID校验，审计人员能够看到正常解释、资料缺口和待索取资料，并最终人工决定是否保留线索。**补充资料续分析已确认为交付目标**：在主链通过后，应能演示“待索取清单 → 授权脱敏模板资料 → 绑定风险卡局部重跑 → 更新缺口/人工确认”的闭环；若截止前仍未跑通，材料必须明确写“未完成”，不得静默删除目标或用线框冒充已运行。

如果RAG、第二案例、续分析或正式对比未达到验收，材料必须如实收缩到已通过的主链；不能用静态截图、缓存或远期功能代替真实能力。
