# 交付物 C：创新点竞争力报告

## 一、结论先行

真正值得在决赛讲的是**一个内核 + 一个机制**：

1. **内核：跨报告指标语义对齐 + 口径兼容判断**（不是"找相同数字"，而是先证明"能不能比"）。
2. **机制：证据约束的分级判定 + AI 主张必须被程序复核**（规则定证据、模型提主张、程序裁决级别）。

"七个智能体""RAG 知识库""证据定位"都不足以单独构成创新，建议降级为辅助技术；"知识库提升准确率"应删去。

---

## 二、逐项创新评估

### 创新 1：口径兼容性先于数值比较（建议重点讲）

| 维度 | 内容 |
|---|---|
| 业务问题 | 年报与可持续报告的同一指标常因合并范围、期间、单位、定义不同而不可直接相减；直接比数会产出大量假差异。 |
| 技术实现 | 五项前提（主体/期间/定义/范围/单位）分别要求**可回查原文**；任一前提未支持时，正式差额与残差字段**置空**（`formal_blocked`），只保留假设试算。 |
| 相比传统方法的增量 | 普通规则程序只会"取值—比较—报差异"；普通大模型会"读完就给结论"。本系统把"能不能比"变成可审计的前置判定。 |
| 可验证证据 | 对抗样本 B2（合并 vs 母公司）只建立叙述关系、B3（期间不同）不建立关系、B1（单位不同）正确换算；24 样本口径判断准确率 8/8。 |
| 成熟度 | **高**（代码完整、规则明确、可复现） |
| PPT 表达 | "我们不是比数字，我们首先证明这两个数字能不能比——五项前提，每一项都要能回到原文。" |

### 创新 2：AI 主张不能自我成立，必须由程序复核（建议重点讲）

| 维度 | 内容 |
|---|---|
| 业务问题 | 大模型最危险的不是算错，而是**用一句像证据的话把前提"说成成立"**，从而产出看似严谨的错误结论。 |
| 技术实现 | 模型提交的条件状态一律降级为 `unknown` 并记 `condition_demoted`；范围依据需程序逐成员复核（引文必须同时含本指标名与边界词）后才重新采纳；数值、算式、结论级别始终由程序生成，模型字段在整合时被剥离。 |
| 相比传统方法的增量 | 普通 RAG/Agent 只做"引用必须存在"的子串校验；本系统要求"引用必须**支持该前提**"，且复核结论可回查。 |
| 可验证证据 | 对抗样本 C3：修改前同一输入被判为"未解释差异"（错误结论），修改后为"依据不足"；8 项回归测试中 `test_model_asserted_condition_is_demoted_on_integration` 直接覆盖。 |
| 成熟度 | **高**（本轮新增，含回归测试） |
| PPT 表达 | "模型可以提主张，但不能给结论。它说'口径一致'，我们要求它指出原文；指不出，程序就把这条前提退回未证实。" |

### 创新 3：区间算术与"假设下相容"的分级（建议作为技术亮点讲 1 页）

- 金额用十进制与区间表示，残差区间含 0 才算"假设下相容"，不等于"一致"。
- 比例类指标按显示位数识别舍入相容，避免把 1.11% 与 1.1083% 误报为差异（本轮修复）。
- 可验证证据：E1/E2 从"未建立关系"变为"假设下相容"；金额同值关系仍保持严格口径（未声明舍入不解释差额）。
- 成熟度：高。表述建议：不要说"我们的算法能处理不确定性"，而说"我们把'看起来一样'和'真的能比'分成了两个字段"。

### 创新 4：多位置/多版本证据冲突（建议辅助讲，不单独成页）

- OCC-001 保留每一处披露的残差，不取平均、不取首个；G1/G2 两处不一致在修改后可判为"报告内前后披露不一致"。
- 局限：多位置检查不构成跨报告结论，页面上必须写明。

### 创新 5：知识库 RAG（**建议降级表述**）

- 事实：知识检索片段进入提示词，但消融实验显示开关对候选结果无影响。
- 建议说法："知识库提供准则与行业线索，帮助模型理解指标含义；目前尚未证明它对最终结论有独立贡献。"
- **不要**说"RAG 提升了核验准确率"。

### 创新 6：七智能体（**建议删除该表述**）

- 事实：代码只有 A1/A2/A3 三个模型角色，A4—A7 不存在。
- 建议说法："三个模型角色分别负责发现、补证与独立研判，外围由确定性核验与门禁把关。角色少是有意的：能用程序判定的事情不交给模型。"

## 三、与三类基线的对比（如实标注）

| 维度 | 人工核对 | 普通大模型（未测） | 传统规则程序（部分可推演） | 本系统 |
|---|---|---|---|---|
| 差异识别 | 依赖经验，慢 | 未测 | 只能同名字段精确比较 | 24 样本差异查全 8/8（合成） |
| 复杂口径理解 | 强，但不可复现 | 未测 | 无 | 口径判断 8/8（合成） |
| 证据可靠性 | 工作底稿 | 未测 | 无原文定位 | 引用逐字校验，100% 可回查（合成） |
| 误报 | 低 | 未测 | 高（不判口径） | 合成样本 0 误报 |
| 人工复核成本 | 高 | 需逐条核 | 中 | 每条结论附原文、算式与缺口 |

**未测项必须说明**：本轮无模型 Key，未运行 ChatGPT/DeepSeek 对照；"普通大模型"一列全部标"未测"，不得在答辩中给出数字。

## 四、建议的 PPT 结构（三页讲清创新）

1. **问题页**：同一指标两处披露不同，专业人员的第一个问题不是"差多少"，而是"能不能比"。
2. **机制页**：五项前提 → 任一未证 → 正式差额置空；AI 提主张 → 程序复核 → 才采纳。配 C3 修改前后的对照（错误结论 → 依据不足）。
3. **证据页**：24 个对抗样本 15→22 通过；币种未知 13.3%→0.77%；并明确写"真实报告仍无正式结论"。
