# 独立标注与人工试用交接包

本包有21个候选问题，覆盖7家企业、15份经SHA-256核对的公开报告。6题为开发对象，15题来自未配置企业专用候选规则的公司，暂记candidate_holdout。它们尚未经过独立人员标注，不能称为已经验证的测试集。格力未取得独立的资源效率候选，coverage中如实保留缺口。

## 可以直接交接的材料

- `annotator-A.json`与`annotator-B.json`：分别交给两位独立作答者。不要让他们先看系统输出，也不要交换答案。
- `cases.json`：冻结的问题、题号、资料范围、事项编号与证据包位置。
- `sources.json`：登记来源、报告哈希与解析覆盖；报告全文不重复提交到公开仓库。
- `freeze.json`：任务清单哈希及生成状态。任何题意修改都应另立版本。
- `human-status.json`：目前没有人工结果，准确率、工时中位数均没有填成0。
- `baosteel-table-source-check.json`：真实原件表格取证的开发检查，不是人工金标，也不证明跨报告金额一致。

## 独立作答工具

打开线上 `/assets/validation-study.html`，页面会加载任务清单。也可以手动选择A/B任务包。先填写协调人分配的匿名编号，选择“独立人工答案”，按任务独立阅读原报告，填写标签、判断理由、PDF页码和原文依据，导出本题JSON交回协调人。

本页不会调用模型、展示系统答案或自动上传作答。保存文件前的计时不代表已接受该答案。两人意见相同也要保留两份原始文件，分歧由实际复核者另行处理。研究参与者的身份和是否真实使用，需要协调人确认；程序不能认证其专业身份。

## 人工与系统辅助比较

另找4—6位实际参与者开展小规模交叉试用，人数只是建议。先使用不纳入正式分析的练习题。将正式题分成难度近似的A/B两套，分别安排“先人工后辅助”和“先辅助后人工”，平衡题目与顺序。任务与顺序由协调人事前记录，不能根据结果临时挑选。

人工条件允许约定的PDF搜索、Excel等工具；辅助条件增加AuditTrace。两种条件提交同样的结论、证据、口径判断和未决事项。辅助时间包含模型等待、回查、纠错和导出。不要让已经给某题标过金标的人再给该题做计时，也不要让同一个人先人工做某题后再用系统做同题比较速度。

在作答页选择“人工与系统辅助计时试用”，按分配条件开始。计时开始后锁定身份、题目和条件；刷新会保留起点和草稿，等待时间不会丢失。作答后导出JSON。系统不会把参与者自己的满意程度当作专业质量评分。

## 独立质量评阅

先移除底稿中可暴露实验条件的界面痕迹，再交给另一位实际评阅者。按相同规则检查：

1. 结论与证据边界合理，问题得到回答；
2. 重要事实有可打开的原文支持，报告、主体、期间和金额归属没有混淆；
3. 未决条件及下一步资料明确；
4. 没有重大错误。把预算当实际投入、错误主体/期间、编造或错引原文、无据认定实际入账，均属于重大错误；
5. 文字与排版等小修改另记，不借此掩盖专业错误。

质量评阅文件采用下列结构。所有字段由实际评阅者填写，不要将空白模板放进待导入目录：

```json
{
  "purpose": "review",
  "session_id": "对应参与者导出的真实session_id",
  "reviewer_id": "实际评阅者匿名编号",
  "quality_accepted": false,
  "major_errors": 0,
  "conclusion_correct": false,
  "evidence_supported": false,
  "reason": "填写实际评阅意见"
}
```

示例中的false、0只是文件格式说明，不是本项目实际结果。是否正确和重大错误数必须重新填写。评阅者不能给自己评分。

## 导入和分析

将真实导出文件放入单独的本地目录，不要上传带个人信息的资料至公开仓库：

```bash
python scripts/analyze_human_validation.py --manifest docs/competition/validation/cases.json --responses-dir /path/to/actual-responses --gold-output /path/to/labelled-cases.json --report-output /path/to/human-study-report.json
python scripts/compute_iaa_metrics.py --cases /path/to/labelled-cases.json --task-type relation_tracing --output-report /path/to/iaa.json
```

导入器核对题号与问题，拒绝同人重复充当两位标注者；人工计时必须另有独立质量评阅，学习效应和自己评分的记录不会计为有效比较。结果只提供描述性时间和合格交付率，不能凭小样本直接声称普遍提效。

## 后续真实模型比较

从cases.json取出目标任务的report_set_id、matter_id、as_of_date、case_id及evidence_ids_file。四组为G1/G7/G6/G3，所有组使用同一代码版本、问题与固定输入。端到端模式另立批次。使用run_render_comparison.py执行，密钥始终留在Render；不要在本地复制密钥。

正式评测前冻结人工答案并核对案例映射。任何用于发现问题后修改提示词或规则的案例，移入开发集并重新取测试样本。候选来源真实、模型调用成功和业务答案正确，是三种不同证据。
