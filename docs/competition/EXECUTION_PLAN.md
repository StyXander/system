# AuditTrace 科创杯完整执行清单（融合任务版）

本清单按任务内容组织，每项明确工作、交付物和验收要求。全部任务用于科技发明制作B类备赛及相应技术验证。涉及外部检测、正式查新、专利申请、扩展评测的任务，依据技术评估、预算和实际资源决定执行范围。

本轮更新依据学校正式通知、三页评审附件、老师对软件参赛形式的答复、上一版清单及用户补充方案。代码问题沿用已核对的main提交47eeacabb5da1081565a19d831ba4c12674ac522，实施时重新获取最新main。代码结论属于静态审查，真实模型实验和专业效果仍待执行。人数、样本量、报告篇幅及视频时长属于内部建议，正式申报以本届系统和补充通知为准。

- [ ] 再完成端到端实验，各组访问相同报告集合并自主检索，检索和计算均纳入预算。
- [ ] 用G7与G1、G3与G6比较约束效果，用G6与G1、G3与G7比较工作流效果。
- [ ] 若声称A4独立有效，比较定向反证与等预算普通复核，检查新增证据和判断修订。
- [ ] 若声称A3独立有效，在确实需要跨期信息的任务上比较，控制可访问报告年度和观察时点。
- [ ] 初步建议每项重复3次，保存全部运行，按整套测试轮次计算指标和波动。
- [ ] 依据实际成本补充预算档位比较，保留简单事项与复杂事项分组结果。
- [ ] 评分时尽量隐藏配置名称，记录标注与评分人员是否知道分组。
- [ ] 将使用过的正式测试错误用于修复后，另取新样本复测。

### 8.4 指标及结果报告

| 指标 | 报告要求 |
|---|---|
| 任务正确性 | 预定标签准确率、Macro-F1、混淆矩阵及实际类别数量 |
| 错误确证率 | 错误确证数/全部确证数，分母0为N/A，确证定义事前确定 |
| 正确确证召回 | 正确确证数/金标可确证数 |
| 确证覆盖率 | 系统确证数/全部业务样本数 |
| 证据支持 | 引文是否存在、是否支持具体主张分别评分 |
| 证据定位 | 使用可接受且允许等价支持的证据集合评估 |
| 纠错效果 | 错误改正确、正确被误改、仍未解决 |
| 工程表现 | 完成率、失败和部分完成、耗时、实际用量及可核对成本 |

- [ ] 展示原始计数、比例的分子分母及样本限制。
- [ ] 重复运行不冒充独立样本，同企业事项相关性纳入统计解释。
- [ ] 扩大数据后采用适当的配对或按企业聚类的置信区间，样本小时展示不确定性。
- [ ] 将没有改善、拒答过多、成本偏高和失败结果列入报告。
- [ ] 禁止预填G1会误判、G3一定正确或降低若干百分点等结果。

### 交付与验收

交付实验协议、配置文件、完整运行JSON、评价代码、结果表和统计图。每个数字能定位到原始任务，实验结论与被控制的变量一致。

## 九、功能、性能、可靠性与失败分析

### 执行任务

- [ ] 验证同时处理任务、并发结果合并及重复请求的一致性。

### 交付与验收

## 十、软件著作权与发明专利

### 10.1 软著任务

- [ ] 核对实际开发者、权利人、合作开发或学校相关权属要求。
- [ ] 核对仓库中的软著材料是否存在、能否打开及是否对应实际版本。
- [ ] 检查所谓60页源码文档是否满足当前登记要求，源程序和说明文档分别准备，页数不足时按真实规模提交。
- [ ] 核对软件名称、版本、完成与发表情况、申请人及签署信息。
- [ ] 准备操作说明、程序鉴别材料、申请信息和所需证明文件。
- [ ] 按官方办理系统提交，保存提交凭据、实际受理记录、补正和登记证书。
- [ ] 编写软著办理操作说明，标明材料与系统字段对应关系。
- [ ] 申报材料按已提交、已受理或已登记分别表述。

登记办法规定受理后60日内审查完成，提交、受理及补正需分别考虑。清单不承诺取得受理通知或登记证书的具体日期。

### 10.2 专利任务

- [ ] 请学校知识产权服务人员或适当专业人员评估具体软件技术方案。
- [ ] 检索相关专利和论文，形成技术特征比较。
- [ ] 核对GitHub、比赛演示和其他公开内容及其时间，评估对新颖性的影响。
- [ ] 在确有可申请技术方案时编制发明专利交底书，交底题名由实际创新内容确定。
- [ ] 交底书写明现有技术、技术问题、具体方案、步骤与数据结构、附图、变体、效果及已公开内容。
- [ ] 将拟保护点对应到实际代码和测试结果。
- [ ] 核对申请人、发明人、权属、材料和申请成本，经相应授权后办理正式提交。
- [ ] 保存申请凭据、申请号、受理及后续审查状态，后续按真实进展维护。
- [ ] 如评估后不适合申请，保存评估理由并调整成果材料。

国家知识产权局对电子申请的公开答复有较快出具受理通知的办理说明，但实际取决于材料和办理状态。受理仅证明申请进入相应程序，技术新颖性和创造性仍需审查。软件方法通常不属于实用新型保护范围。已公开技术与法定例外需具体评估。

### 交付与验收

交付软著材料包、操作说明、真实办理凭据和专利评估记录。选择申请发明专利时，补充完整交底书及实际申请进展。各材料分别标注工作稿、已提交、已受理和已授权等状态。

## 十一、真实试用、专业评价与效益测量

### 执行任务

- [ ] 收集实际问题和专业意见，形成修复清单并复测。

### 交付与验收

交付模板、真实试用记录、经确认的证明或评价、问题整改记录及效益计算依据。取得盖章时按章所确认内容表述，签署形式不能替代过程数据。
