# 独立人工标注与复核规程

标注员根据原报告回答一个事前固定的问题，先独立完成，再由复核人处理分歧。系统输出与实验组别在首次标注时不提供。开发案例允许讨论和修改，进入正式测试后须冻结版本。

## 每题记录

case_id、question_id、企业及项目簇、report_set_id、matter_id、明确主张、观察时点、原件SHA-256、报告年度及发布日期、PDF页码、逐字引文、项目主体、期间、范围、单位、计量基础、理由、可接受等价证据、标注员身份与复核记录。资料缺失允许作为结论，不能把无法判断改成无冲突。

## 判断顺序

1. 核对任务究竟询问项目关系、金额可比性、数值调节还是承诺进度。不能用数值一致标签评价项目关系题。
2. 核对名称以外的身份信息，包括子工程、地点、建设阶段及归属依据。名称相近不足以合并。
3. 对金额题，核对主体、期间、定义、范围、单位、币种和计量基础。明确错配与尚缺信息分别记录。
4. 在条件满足时，列出原值、公式、舍入及容差，重新计算。破折号含义不明时保留缺失。
5. 检查替代解释是否有证据，记录能区分解释的新增资料。

## 金额核验题标签

| 标签 | 使用条件 | 常见误用 |
|---|---|---|
| CONFIRMED_CONSISTENT | 同一事项、口径可比、所需值齐全，程序复算在预定容差内 | 将同一项目或金额接近直接写成一致 |
| NOT_COMPARABLE | 已有证据表明关键口径不同，当前没有有效调节桥梁 | 把任何缺资料都写不可比 |
| INSUFFICIENT_EVIDENCE | 身份、口径、原值或解释中有关键缺口，无法作确定判断 | 以没有发现冲突代替证据齐全 |
| SUSPECTED_CONFLICT | 可比性与原值已充分核实，差异仍未获得有效解释 | 将预算与实际的差异叫财务冲突 |
| EXPLAINED_DIFFERENCE | 已核实差异，并有足够证据支持具体调节解释 | 一个合理猜测就认定已解释 |

同时标注relation_support与amount_comparability。关系标签为supported、limited、pending、conflicting、not_comparable或invalid；金额标签为comparable、not_comparable、needs_evidence或not_assessed。生产系统的关系支持不自动证明数字相等，当前五类金额投影只能保守使用，不能把它当成完整金额研究系统。

## 证据评分

引文存在与支持主张分开评价。原件哈希、页码与文字相符只能证明摘录可回查；标注员仍须判断证据支持了哪一步。每条主张按支持、部分支持、不支持或无法判断记录，并保留理由。同一页存在金额但不属于同一工程，属于不支持该金额归属。

## 分区与冻结

同一项目的别名、子工程和不同年度放在同一分区。正式集按企业或项目簇隔离，防止开发时见过答案。可使用6项开发问题及16项初步挑战问题，但实际数量由可用证据决定；不足时如实缩减。人造材料单独标明，不能与真实披露混算。

两名不同人员分别填写annotations中的annotator_id、verdict、evidence_ids、reason、completed_at。分歧由第三人填写adjudication.final_verdict及理由。缺失、非法标签和同一人员重复填写不得计入独立一致性。只有一个类别时Kappa可能不可定义，应报告原始一致率及类别分布。使用compute_iaa_metrics.py计算，结果不预填。

## 复核交接

保存原始两份标注、冻结文件哈希和复核修改记录。模型实验后才发现的题意错误应登记为任务缺陷；修改后另立版本，不能无痕改金标提高结果。先前用于修复的正式题进入开发集，新取样本复测。
