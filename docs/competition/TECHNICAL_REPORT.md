# 审迹智链跨报告财务关联证据核验系统综合报告

## 作品概况

审迹智链AuditTrace面向年报与可持续发展报告中的同一事项，整理财务关联证据、检查金额口径并提出后续资料需求。当前重点场景是绿色转型项目与环保投入，主要使用者为财务及可持续报告编制复核人员、审计与鉴证项目组。作品以可运行软件参加科技发明制作类评审，原件核验、工程回归和实际运行记录分别提供支撑。

一次调查限定为一家企业、一个事项和一个明确问题。例如，年报附注中的炼钢工程能否与ESG报告中的近零碳工厂建立关系，该行转固金额是否足以说明整个项目投资已完成。系统分别保留有依据的关系、尚不能确认的金额口径与需要索取的内部资料。

本报告随代码版本维护。模型调用、专业正确性、外部试用和知识产权登记分别记录，实际实验结果见随附测试报告。没有独立人工标签的运行不报告准确率，也不用于宣称优于通用模型。

## 业务问题与使用阶段

可持续发展报告常按战略、项目和绩效叙述，财务报表按会计确认及披露要求组织。相同项目可能在正文、在建工程附注、固定资产、现金流量表与会计估计中分散出现。两份材料提及相近名称或金额，只能构成检索线索，仍需检查企业主体、工程范围和期间。

总体规划投资表示计划规模，本期在建工程增加反映一定期间的工程成本，转入固定资产反映分类变化，付款又涉及应付款与预付等项目。直接将其中两项相减，不能确认企业存在矛盾。系统先列出这些条件，再决定是否能够执行程序核算。

对已发布公开报告开展核查，适用于披露复核、鉴证前的证据整理和资料需求设计。编制阶段也可以参考同样流程，但当前已验证资料入口是登记公开报告，不能据此承诺任意内部文档均可直接处理。项目组取得合同、验收记录、转固凭证或资产卡片后，仍须执行专业程序。

政策背景详见POLICY_BASIS.md。财政部基本准则涉及报告主体、信息关联及数据假设等要求，各交易所适用范围应分别核对。规则提供业务需求依据，技术先进程度仍须通过比较和实际效果说明。

## 相关工作与技术定位

FinQA和TAT-QA已研究财务数值推理及表格文本联合处理；ConvFinQA进一步处理对话中的连续数值推理。ReAct研究模型推理与工具调用，Self-RAG研究检索与自我评价，ALCE将引用质量列为独立评价问题。财务问答、工具调用、反思和引用均有既有技术基础。

本作品围绕跨报告业务增加约束与交付结构：关系支持和金额可比性分别保存；模型建议必须引用当前账本中的证据；来源、期间与操作数身份满足条件时才进行复算；反证、分歧和未决条件进入资料清单。技术差异能否带来业务收益，分别通过规则组件对照、工作流对照与修订测试验证。

Workiva官方介绍可持续数据与报告管理，MindBridge介绍财务交易风险分析。它们的资料输入和业务范围与本作品不完全一致。当前比较依据官方功能介绍，未取得同任务实测，不能据此宣称市场没有同类工具。文献及产品出处见RELATED_WORK.md。

## 系统总体流程

用户选择同一企业的登记报告，建立带观察时点的不可变资料集合。原件保留官方来源、年度、发布日期、页数和SHA-256。程序解析PDF并记录成功、失败和扫描页，形成可定位的原文块。原件验证说明文件与摘录的来源身份，语义是否支持主张另行判断。

候选档案阶段不调用模型，按单处披露登记事项。用户选定一个事项后启动真实调查。A1复核身份与别名，A2追踪财务路径，A3检查跨期事件与承诺，A4检查竞争解释，A5综合意见并提出补证。程序检查各角色输出后合入共享档案，角色不能直接覆盖他人状态。

结果页展示当前判断、原文证据、财务落点和待补材料。历史结果从保存版本恢复，无须重新调用模型。查看旧任务和运行新任务使用独立上下文，导出读取保存结果，保持JSON、CSV和Word来源一致。

## 关键数据结构

| 对象 | 保存内容 | 约束 |
|---|---|---|
| ReportSet | 企业、文档ID、指纹、年度与观察时点 | 同一集合不能无痕更换原件 |
| MatterEvidence | 哈希、PDF页码、引文、提取方式和来源状态 | 失效来源不能继续当作有效证据 |
| SustainabilityMatter | 项目名、别名、主体、地点和身份依据 | 候选名称不自动确认跨报告同一性 |
| FinancialImpactPath | 分段机制、财务项目、证据和支持状态 | 原文、假设、计算和人工意见分列 |
| MatterAssessment | 关系支持、金额可比、承诺、未决条件 | 关系支持不自动转为金额一致 |
| CompetingExplanation | 解释、支持、反证与区分资料 | 合理假设不等于已证实解释 |
| 调查回执 | 角色、工具、预算、失败、用量和版本 | 跳过、失败和未知用量如实保留 |

## 会计口径约束与程序核算

系统检查主体、期间、定义、范围、单位和计量基础，识别预算与实际、累计与本期、母公司与合并范围以及总体工程与子工程的差别。关键条件不明时保留needs_evidence，明确不同且没有调节桥梁时记录not_comparable。模型不能仅凭金额接近自行判定可比。

数值工具只使用已定位原值，以Decimal运算。操作数必须有期间、范围、单位和币种，拒绝重复操作数及不满足精确性条件的数值。项目身份、计量基础和去重依据须有可回查证据。算术结果与项目归属语义分开，条件试算不能冒充企业实际财务影响。

宝钢年报第154页炼钢子工程披露期初240,078,904.49元、本期增加847,336,295.51元、本期转固1,087,415,200.00元。三项已知值按期初加增加减转固，试算结余0.00元。相关转出和期末列出现破折号，其含义未明确，系统只报告已知三项试算，保留完整勾稽所需的缺失条件。

## 证据修订与反证

反证调查针对具体主张检查替代解释。整体工厂投产不能直接证明每个子工程同日转固；一般固定资产政策不能证明某项资产已达到预定可使用状态。A4记录各解释的支持材料，以及能区分解释的验收、项目编码或资产台账。

角色建议在副本上校验事项版本、引用身份、事件年份和关系端点。失败时不把不完整建议写入档案。单模型综合建议同时包含多个对象时，应先登记路径、事件和承诺，再解析关系，否则合法前向引用可能被误拒。本轮真实模型开发测试发现端点拒绝问题，修复增加共享临时ID映射与整体提交验证，并让单模型获得同等的一次校验反馈修正机会。

来源变更、身份归并与人工修订保留前后版本。人工采用是使用者的处理决定，不能使模型输出自动取得审计鉴证效力。未决条件与资料清单用于支持进一步核查。

## 技术效果验证设计

核心比较为2乘2设计。G1为单模型关闭门禁，G7为单模型开启门禁，G6为五智能体关闭门禁，G3为完整五智能体。各组使用同一底座模型、温度、事项、报告集合和预算上限，保留来源及引用校验。单模型允许多轮自检和工具使用。

固定证据实验冻结候选包并保存证据ID和内容哈希，所有角色使用同一输入。端到端实验另行测量检索与执行能力，两者不混算。比较运行关闭完整系统特有的额外定向补查，宝钢结构化表格向各架构统一提供。

专业效果需要两人独立标注并复核分歧。金额核验与关系任务使用各自标签，分类正确性、错误确证率、正确确证召回和覆盖率一起报告。没有确证时错误确证率为N/A，技术失败单独计数。当前生产事项合同没有明确数值一致状态，不能把关系支持强行写成确认一致。

每次运行保存完整JSON、任务ID、模型返回标识、回执、Token、耗时和停止原因。未核实计价时费用保持空值。比较时同时检查证据哈希、代码版本和实际用量，调用次数上限相同不等于实际等成本。用于修复的开发病例不再作为未见独立测试。

## 三家真实企业案例

宝钢档案关注零碳工厂整体与炼钢子工程的关系，记录年报及ESG原文、表格试算、范围和折旧起点缺口。该例展示已有财务证据与仍待验证的语义条件同时存在。

五粮液档案关注ESG环保投入1.8亿元的财务分类。取得的片段说明投入披露及一般会计政策，尚不足以将总额分配到资本开支、当期费用和现金付款。底稿列出环保投入明细及项目编码需求，不凭总额估算落点。

美的档案关注气候风险披露与财务估计。ESG对气候情景、风险和资产影响的陈述可与年报减值政策形成调查问题；一般政策不能证明气候因素已经进入某项估值。该例保留证据不足状态和所需测算资料。

三例均使用真实登记资料。五粮液和美的离线候选档案不冒充完成五智能体调查，三份底稿亦不代替外部专业复核。精选案例说明工作过程，不替代独立测试集。

## 软件交付与现场展示

正式入口为backend.app.connectivity_app:app，配套Python依赖清单、启动脚本及配置示例。真实模型使用服务器环境配置，网页和实验脚本不读取或下载Render密钥。运行记录对应部署提交，模型配置存在与请求成功分别验证。

核查工作室采用顶部导航、暖白工作区与横向工作阶段，集中呈现资料、判断和证据。宝钢页保留工厂原图和证据图谱。现场从已完成历史任务回查原文并导出底稿时，应明确说明历史回放。

演示依次明确问题、展示工程范围、核对年报原值、查看反证与补证需求、导出保存版本。网络异常时使用保存底稿和回放材料，保留原任务编号。支持的操作系统和外部模型依赖以操作手册为准。

## 成果状态与应用测量

作品已具备源码、在线软件、技术方案和可追溯运行记录。既有软著源码鉴别文档需要随版本核对，登记状态以实际提交及受理凭据为准。技术交底用于知识产权评估，不能作为授权专利证明。

试用应由真实用户完成具体任务，记录操作、采用与修改、总工时和未解决问题。量化效益需包含人工审阅及修正时间，并控制熟悉效应。签署、印章和使用效果由实际参与者确认。当前不填报未经测量的提效比例、收入或客户数量。

## 限制与验证边界

公开报告通常不能提供工程验收、转固凭证、付款明细和项目级预测，系统须保留资料需求。扫描页、跨页表格、别名归并和模型结构错误可能造成覆盖不全或执行降级。完整系统也可能增加用量并误拦截合理关联，实验应公开这些结果。

成熟性主要由可运行交付、真实回执、来源回查及失败修复说明。先进性需要扩大独立样本、完成专业标注并比较效果。现有技术差异已经落实到代码和实验入口，成果表述应随实际验证范围调整。
