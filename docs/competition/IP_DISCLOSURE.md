# 知识产权材料与技术交底工作稿

## 软著办理

核对权利人、开发者、合作开发及学校权属约定。仓库既有docs/copyright目录及60页文档需要逐页核对版本、名称、源程序连续性和文档要求。程序不足规定页数时按真实规模办理。准备登记申请、程序与文档鉴别材料及权属文件，按官方系统提交并保存实际状态。

## 发明专利交底工作稿

拟议名称为一种具有会计口径约束和证据修订机制的跨报告核验方法。最终名称和保护范围由技术评估确定。

现有技术包括通用检索问答、财务表格文本推理和多智能体协作。具体区别应由检索结果补充，当前不主张已证明新颖性。

待解决问题为不同项目及金额口径被错误关联、证据更新后旧结论仍被采用。

具体流程包括登记原件及指纹、定位事项及实体、形成带主体期间范围和计量基础的关系、检查约束、在条件满足时核算、定向寻找竞争解释、更新相关关系及依赖结论、保存版本与原文定位。

实现依据包括connectivity_matter_schemas.py、connectivity_matters.py、connectivity_matter_revision.py及connectivity_matter_pipeline.py。待保护点、变体和附图需结合独立技术贡献补全。

实际效果【待独立测试】；相关专利比较【待检索及专业评估】；申请人与发明人【按真实贡献确认】；GitHub及演示披露范围【逐项核对】。

已公开技术可能影响新颖性，应提交学校知识产权服务人员评估。正式申请、缴费、权属确认及签署由相应权利人办理。当前文件为交底工作稿。

## 技术交底补充

### 数据对象

原件记录D包含document_id、file_sha256、report_type、report_period与disclosure_date。证据E包含D的身份、PDF页码、quote、提取方法及有效状态。事项M保存名称、主体、地点、别名及身份来源。关系R记录source_id、target_id、relation_kind、assertion_origin和evidence_ids。综合意见A将relation_support与amount_comparability分开，并保存unresolved及next_actions。

### 方法步骤

S1 通过登记来源取得原件，以文件指纹验证字节身份，建立包含观察时点的不可变报告集合。原件变化后保留旧指纹，不将旧引文继续标成有效。

S2 从PDF正文与表格提取带页码的候选证据，记录扫描、失败和提取覆盖。按单处披露生成事项候选，名称只作为线索，主体、地点、子工程范围和阶段需另行核对。

S3 让识别角色提出事项归并，程序检查各原始证据是否保留、来源是否有效以及项目名称锚点。证据不足时保留独立候选，不强制完成跨文档归并。

S4 按财务路径、跨期与竞争解释分配调查任务。模型只能请求登记范围内的工具，调用轮数和总请求由服务端预算控制。工具回执与失败均进入日志。

S5 每条财务路径保留分段主张、原文或机制假设、引用及支持状态。核对主体、期间、范围、单位和计量基础，条件缺失进入补证，不由模型文字直接放行金额。

S6 将已定位的精确数值作为操作数，以Decimal进行条件试算。校验重复数值、期间范围、币种和计量依据。已知分量的算术平衡与完整会计调节分别标识。

S7 将角色建议在副本上验证，检查所有引用和关系端点。综合建议先登记全部路径、事件和承诺，再通过同一临时ID映射解析关系。任一环节拒绝则整份不写入；在预算内返回明确字段错误，允许一次修正。

S8 反证角色针对已有路径提出可区分的解释，保存支持、反证及所需资料。综合角色分别给出关系、可比性、承诺和阶段判断；取得新证据后保留前后修订记录。

S9 从同一保存版本生成页面、JSON、CSV和Word，附原件定位与未决问题。历史回放不重新请求模型，人工采用另存处理身份和理由。

### 拟讨论的技术特征

第一项为证据与状态的分层保存及失效传播。第二项为金额放行前的身份和口径条件，以及确定性运算与语义判断的分离。第三项为多对象建议在副本中先登记对象、再解析引用、整体提交的集成机制。第三项属于通用软件工程也可能存在的处理方式，不能仅因本项目首次修复就声称具有专利创造性。

### 实施例与变化形式

宝钢实施例使用年报第154页的三项已知数值，并保留破折号含义和总体/子工程范围缺口。其他实施例可处理气候风险对估计的路径，但没有直接证据时保持机制假设。角色数量、模型供应商和存储可变化，来源校验、语义条件和提交一致性不随模型数量取消。

### 公开与权属核对

登记GitHub每次公开提交、比赛演示、论文或网络材料的首次公开时间及具体特征。列出每位实际发明人的技术贡献，并核对学校项目、资助、导师及合作单位的协议。代理评估应比较权利要求层面的已有方案，不将本文件的定向文献记录称为正式专利检索结论。

## 软著字段与材料对应

| 办理字段或材料 | 对应文件与填写原则 |
|---|---|
| 软件名称与版本 | 以最终申报名称和实际发布版本统一填写，不能从历史文档直接照抄旧定位 |
| 开发完成日期与发表情况 | 依据真实开发和公开记录填写；GitHub公开情况应如实核对 |
| 著作权人及开发方式 | 按真实权属及合作协议填写，不能自动推定队长独占全部权利 |
| 程序鉴别材料 | 保留完整源程序的确定顺序、原文件行号与哈希，前后选段不得靠增删空行凑数 |
| 文档鉴别材料 | 用户操作说明及真实系统界面；登记要求与赛事说明书分别核对 |
| 证明文件 | 依权利人类别与实际开发关系准备，签署由本人确认 |
| 实际状态 | 未提交、已提交、补正、已受理或已登记，分别附对应真实凭据 |

本轮新增材料未执行正式登记或专利提交。取得学校权属意见和申请人确认后，才能在官方办理系统完成相应签署及提交。
