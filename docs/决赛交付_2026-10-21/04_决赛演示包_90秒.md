# 交付四：决赛演示包（90 秒）

## 一、必须先接受的三个事实

设计演示前先把约束说清楚，否则现场会崩：

1. **一次真实运行约 150–195 秒。** 本机实测：纯计算模式 149.6s（页面记录）/ 193.6s（含首屏与轮询）。90 秒内无法完成一次完整运行。
2. **历史记录按浏览器会话隔离。** 换浏览器或清 cookie 后看不到之前的运行（`store().list_owned(owner(request))`）。因此演示机必须在**同一浏览器**里预跑一次。
3. **刷新不会自动回到结果页。** 刷新后回到「新建核验」；恢复路径是「历史记录 → 打开记录」。演示中不得刷新。

结论：**现场演示采用「预跑 + 历史回放」**，并在开场明确说明。这不影响真实性——回放的是同一台机器、同一份 PDF、同一次真实执行的结果，可随时点开历史核对。

## 二、90 秒分镜（实测口径）

| 时间 | 操作 | 屏幕应出现 | 讲解词（照读） |
|---|---|---|---|
| 0–8s | 停在工作台「新建核验」首页 | 五粮液 · 2025 两张登记报告卡 | 「两份报告，一条证据链。今天只演示一件事：**它什么时候拒绝下结论**。」 |
| 8–16s | 点左侧「历史记录」→「打开记录」 | 历史中那条已完成运行 | 「这是刚才在同一台机器上真实跑完的一次，不是演示数据。」 |
| 16–34s | 停在结果页六格 | 正式复算 0/8、条件试算 5/8、有限支持 0/8、依据不足 3/8、口径冲突 0、不适用 0 | 「8 项关系：**0 项正式一致**，5 项只在写明假设时相容，3 项依据不足。」「'暂不能判断' 不等于 '没有问题'。」 |
| 34–58s | 展开「研发投入占营业收入比例 · 公式与分母」 | 算式、披露比例、分母逆推、显示精度假设、残差区间 | 「它没有把 1.11% 和算出来的 1.1083% 说成一致，而是给出：**如果按两位小数四舍五入，差额落在区间内**；企业没声明舍入方法，所以只到 L0 条件试算。」 |
| 58–74s | 展开「研发人员数量 · 年报与ESG披露数值核对」 | 五项前提逐项状态、缺哪一项、所需补证 | 「这一条更典型：数值都在，但**统计范围没有原文**。系统不猜，直接说依据不足，并列出要补什么材料。」 |
| 74–86s | 点「原文」查看 PDF 对应页 | PDF 跳转到引文所在页 | 「每个引文都能回到页码和原句。回不去的，系统不会采用。」 |
| 86–90s | 收尾 | — | 「我们不保证发现差异，我们保证**每个结论都能回到原文**。」 |

### 实测时长说明

- 分镜总长 90 秒，其中 0–16s 为导航、16–86s 为讲解。
- 页面加载与展开的实测耗时（Playwright 记录）：进入结果页约 3.0s，展开关系明细约 0.8s，切原文约 1.5s。因此 90 秒内有约 8 秒余量。
- **不包含**一次新运行（150–195s）。若评委要求现场重跑，明确回答：「可以，需要约 2.5 分钟，我边跑边讲阶段条。」

## 三、核心案例与证据（可提前背）

### 案例 A：研发投入占营业收入比例（假设内相容）

- 规则：`INT-001`（公式与分母）
- 结论级别：`assumption_compatible`，basis_level `L0`
- 计算状态：`not_comparable`（不产出正式差额）
- 关键点：披露比例 1.11%，按分子 ÷ 分母算得约 1.1083%，差额 0.0017 个百分点
- 系统处理：按显示小数位构造区间，判断差额可落在四舍五入范围内；因企业未声明舍入方法，**只给 L0 条件解释，不升级为正式一致**
- 证据位置：五粮液年报 PDF 对应页（研发投入章节表）

### 案例 B：研发人员数量（依据不足）

- 规则：`EQ-001`（年报与 ESG 数值核对）
- 结论级别：`insufficient_basis`
- 缺失前提：统计范围（多为「范围」）
- 系统处理：不生产正式差额，列出所需补证材料
- 讲解要点：**数值相等不代表业务可比**

### 案例 C：环保资本化项目投入（唯一有限支持）

- 报告对：宝钢 600019-2024
- 规则：`ENV-001`（表内合计列与分项列）
- 结论级别：`limited_support`
- 讲解要点：表内结构只能证明「合计列 = 分项列之和」的几何覆盖，**不能证明指标定义、统计范围与期间**。因此是有限支持，不是正式结论。

### 案例 D：AI 自证前提被程序退回（可靠性）

- 三角色模式实测：A1 把 8 个关系的「主体/期间/定义/单位」全部标为 supported
- 程序全部降级为 unknown，轨迹 `condition_demoted`
- 讲解词：「我们没有让第二个模型去评价第一个模型，而是让程序去要原文。要不到就不认。」

## 四、评委追问应对（只答有证据的）

| 追问 | 回答 | 依据 |
|---|---|---|
| 为什么正式结论是 0？是不是系统不行？ | 「0 不是没找到，是五项前提没有同时被原文满足。30 条关系里 8 条给了 L0 条件解释、1 条有限支持、21 条明确列出缺什么。把 0 说成通过才是问题。」 | 交付三第二节 |
| 三角色比单模型强吗？ | 「实测不强。关系召回 8 对 8，成本 4.9 倍，覆盖 6/8 对 8/8。唯一增量是反证条目 4 条对 0 条。我们只说这一点。」 | 交付三第三节 |
| 是不是七个智能体？ | 「不是。是三个角色 A1 发现、A2 补证、A3 复核，加上确定性程序和 Claim 账本。没有七个自主智能体。」 | 代码 `roles = [("A1",...),("A2",...),("A3",...)]` |
| RAG 提升准确率多少？ | 「我们没有做关闭/开启知识库的同输入对照，所以不能说提升。」 | 交付三第六节 |
| 发现多少真实披露错误？ | 「5 对真实报告正式一致 0、已确认冲突 0。我们不说发现了错误，只说给出了 8 条可复核线索。」 | 交付三第二节 |
| 刷新会不会丢？ | 「刷新不会自动回到结果页，但运行结果已落库，从历史记录可以打开。这是已知体验缺口。」 | 交付三第五节 |
| 你们的 AI 幻觉率多少？ | 「没有算幻觉率。我们统计的是 claim 账本里的支持/反证/无据三类，不是幻觉率。给一个通过率当幻觉率是不严谨的。」 | 交付三第六节 |

## 五、应急方案

| 情况 | 现象 | 处理 |
|---|---|---|
| 模型 API 不可用 | 运行只能到「未调用模型」 | **正常演示**：纯计算模式本来就是主演示路径，AI 部分用历史运行截图讲 |
| 页面打不开（线上） | 冷启动慢或 502 | 切本机 `http://127.0.0.1:8899`（预启动），或直接用历史回放截图 |
| 历史为空 | 换了浏览器/清了 cookie | 用同一浏览器重新跑一次纯计算（约 2.5 分钟），期间讲阶段条 |
| 被要求现场跑 | — | 明确说需要约 2.5 分钟，边跑边讲六个阶段 |
| 原文页打不开 | PDF 渲染失败 | 用 CSV/Word 导出里的引文字段证明可回溯 |

## 六、演示前 30 分钟检查清单

1. 启动本机服务：`cd backend && python -m uvicorn app.main:app --host 127.0.0.1 --port 8899`
2. 用**演示专用浏览器**打开 `http://127.0.0.1:8899/#connectivity-root`
3. 跑一次五粮液 · 纯计算，等完成（约 2.5 分钟），确认六格出现
4. **不要刷新、不要清 cookie、不要换浏览器**
5. 打开「历史记录」确认该条在列，再点「打开记录」确认能回到结果页
6. 提前展开一次「研发投入占营业收入比例」和「研发人员数量」，确认无报错后收起
7. 关闭无关标签页与通知，屏幕分辨率 1440×900
