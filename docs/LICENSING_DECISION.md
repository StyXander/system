## 3. 阻断项：PyMuPDF 的 AGPL-3.0

这是本次审查发现的**唯一硬性许可阻断项**。

### 事实

`PyMuPDF` 采用 **AGPL-3.0 或 Artifex 商业许可**双轨授权。本仓库对它的使用不是边缘用法，而是核心链路：

| 文件 | 用途 |
|---|---|
| `backend/app/rag.py`、`backend/app/field_extraction.py` | 逐页文本抽取 |
| `backend/app/source_viewer.py`、`backend/app/connectivity_api.py` | 证据页渲染为 PNG |
| `backend/app/connectivity_extraction.py`、`backend/app/connectivity_bootstrap.py` | 报告解析与就绪校验 |
| `backend/app/cninfo.py`、`backend/app/cases.py` | PDF 身份校验（文件头/页数/企业/年度） |
| `backend/tests/` 7 个测试文件、`scripts/` 1 个脚本 | 测试与验收 |

Python 以 `import pymupdf` 方式进程内链接，属于强耦合，不是可分离的命令行调用。

### 影响

- 若把整个仓库以 **MIT / Apache-2.0** 发布，则发布物包含 AGPL 代码，**与所选许可证冲突**。给项目加一个 MIT 的 `LICENSE` 文件**不能**解决这个问题。
- 若以 **AGPL-3.0** 发布，则合规，但整个项目变为强 copyleft：通过网络提供服务时也必须向使用者提供完整对应源码。
- 仅"删除 LICENSE、不声明许可证"不是解决方案，只是继续保持当前不可再分发的状态。

### 三条可选路径

| 方案 | 做法 | 代价 | 合规确定性 |
|---|---|---|---|
| **A. 全仓 AGPL-3.0** | 直接以 AGPL-3.0 发布，保留 PyMuPDF | 零代码改动；商业使用者须开源其修改；部分企业直接禁用 | **高**（最稳妥） |
| **B. MIT/Apache + 依赖外置** | 只许可自有代码，PyMuPDF 由使用者自行安装 | 需要在 LICENSE/NOTICES 中明确切割；AGPL 的"聚合 vs 衍生"边界存在法律争议 | **低**（不建议在无法律意见时采用） |
| **C. MIT/Apache + 替换 PyMuPDF** | 用 `pypdfium2`（Apache-2.0/BSD-3）做页渲染 + `pdfplumber` 或 `pdfminer.six`（MIT）做文本/表格抽取 | 需改造 8 个模块 + 7 个测试；抽取结果可能有差异，需重跑回归与真实报告比对 | **高**（许可干净，但有工程风险） |

**本次审查不代选。** 建议顺序：若目标是最大化可被外部采用（含 OpenAI 开源项目申请场景），选 **C**；若优先零风险与零改动，选 **A**；**B 不建议**。

## 4. MIT 与 Apache-2.0 对比

| 维度 | MIT | Apache-2.0 |
|---|---|---|
| 复制、修改、分发、商业使用 | 允许 | 允许 |
| 保留版权与许可声明 | 要求 | 要求，且需保留 `NOTICE`（若有） |
| 专利授权 | **无明示条款**（仅有默示许可的争议空间） | **有明示专利授权**，并含专利报复条款 |
| 商标授权 | 不涉及 | 明确**不授予**商标权 |
| 修改文件标注 | 不要求 | 要求标注修改过的文件 |
| 文本长度 | 约 1 KB，一页 | 约 11 KB |
| 企业法务接受度 | 最高 | 高，但需走 NOTICE 流程 |
| 与 AGPL 依赖共存 | 冲突 | 冲突 |
| 与现有依赖（FastAPI/BSD/MIT 等）兼容 | 兼容 | 兼容 |

**本项目具体考虑**：

- 若未来涉及"披露核对方法"被同行采用，Apache-2.0 的明示专利授权对采用方更友好，也更能保护贡献者。
- 若希望门槛最低、便于学生团队与外部研究者直接取用，MIT 更简单。
- 两者都**不能**解决第 3 节的 PyMuPDF 问题。

## 5. 授权范围必须同时明确的事项

即使选定许可证，以下范围仍需所有者逐项确认，否则 LICENSE 覆盖到不该覆盖的内容：

1. **原创代码**（`backend/`、`assets/`、`scripts/`、`tests/`）—— 可许可。
2. **规则索引与专业判断文本**（`backend/app/connectivity_rule_basis.json`）—— 内含对公开准则条款的转述与链接，可随代码许可，但需声明"不是准则原文"。
3. **第三方报告 PDF**（根目录与 `决赛准备/` 中的年报、ESG 报告）—— **不可再许可**，必须排除。
4. **历史竞赛材料**（`决赛准备/`、`archive/`、`docs/` 中的方案书、讲稿、答辩材料）—— 是否随开源发布、是否单独保留，需决定。
5. **示例数据与合成测试数据** —— 需确认是否为纯合成、是否含真实企业信息。
6. **运行记录与评估产物**（`outputs/`、`backend/release_records/`）—— 是否保留在公开仓库。
7. **团队成员署名顺序与版权行写法**（`Copyright (c) 2026 <著作权人>`）。
