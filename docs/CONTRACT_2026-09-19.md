## 二、D1 · 审计关注优先级（已签字，六档）

| 级别 | label（逐字，轨 B 必须产出这个字符串） | 判定条件 |
| --- | --- | --- |
| **G** | 暂不分级（资料/口径受限） | 任一被选用规则返回 `DATA_GAP` 或 `DATA_NOT_COMPARABLE` |
| **P1** | 立即扩大核查 | `screening_status=candidate` ∧ `screening_strength=strong` ∧ `sustained_periods≥2` ∧ `ai_recommendation=retain` |
| **P2** | 优先核查 | `candidate` ∧ `strong` ∧ 不满足 P1 |
| **P3** | 常规跟进 | `candidate` ∧ `standard` |
| **S** | 暂缓判断 | 非 candidate ∧ `ai_recommendation=defer` |
| **P4** | 维持常规程序 | `RULE_NOT_TRIGGERED` ∧ 数据完整 ∧ 无 blocked 行 |

- **判定顺序固定**：`G → P1 → P2 → P3 → S → P4`，不得调整。
- `boundary` 逐字：**「本级别为审计计划阶段的程序筛查信号分级，不是审计认定，不构成审计结论或审计意见。」**
- 铁律：数据缺口只能导致不出级（G），**绝不能使优先级升级**；
  `materiality_assessment` 不折入级别；**不引入任何新阈值**（`>0.08` 已明确否决）；
  `disposition` 是独立轴；级别只能由确定性纯函数产出，**不得由模型直接给出**。
- 命名红线：禁止「风险评级」「信用等级」「无风险」「企业风险等级」、证券评级代码 A1/A2/B1/B2/C1/C2、0-100 分、雷达图。
- 实测归属（供验收比对，非预设结论）：五粮液 → **P2**；标准股份 → **G**。

## 三、D2 · 证据闭合状态（已签字，三档）

| 状态 | label | 判定条件 |
| --- | --- | --- |
| **E1** | 已闭合 | `numeric_gate.passed=true` ∧ 所有 claim 的 `support_status=supported` ∧ 无未解决 `data_gaps` |
| **E2** | 部分闭合 | `numeric_gate.passed=true` ∧ 有直接证据，但存在 `unverified_hypothesis` 或待取得资料 |
| **E3** | 未闭合 | `numeric_gate.passed=false` ∨ 关键 claim 无 evidence 绑定 ∨ `evidence_fitness` 违规 |

输入**只能**来自：Numeric Gate、`evidence_fitness`、coverage matrix、`claim.support_status`、
未解决的 `data_gaps` / `requested_materials`。**禁止让模型直接打 E1/E2/E3**；
与 D1 彼此独立，不得合并成复合分数。实测归属：五粮液 → **E2**；标准股份 → **E3**。

## 四、D4 · 数字闸门可追溯来源范围（已签字，轨 A 已实现）

可追溯来源＝「结构化 field/metric value」**＋**「当前 claim 已实际绑定 `evidence_id` 的 RAG chunk 原文数字」。
这是修正假阳性，不是放松控制。

实现落点（轨 A，2026-09-19）：
- `backend/app/numeric_gate.py`：`validate_numeric_claims()` / `build_numeric_claim_trace()`
  新增 `claim_evidence_bindings: list[{"text": str, "evidence_ids": [str]}]`；
  新增 `_rag_chunk_sources(evidence_bundle, allowed_evidence_ids)`，
  只读 `evidence_bundle["rag_evidence"]` 的原文字段，`source_type="rag_chunk"`、`source_ref=evidence_id`。
- 收紧条件落实方式：
  1. 逐主张分段，每段来源池＝全局结构化来源＋**该段自己绑定的** chunk；
  2. 数字只在未绑定 chunk 中 → 仍 `unverified_numeric_claim`；
  3. 凭空数字 → 仍拒绝；
  4. 不传 bindings 时**完全不引入** RAG 原文来源（无全局白名单）；
  5. `key_unverified_count > 0` 仍判 `incomplete_numeric_claims`（未改名为 success）；
  6. 结构化 field/metric 旧路径由 T4 单测回归保护。
- trace 行新增 `source_type` 对 rag_chunk 的取值与 `bound_by_claim: bool`；
  结果新增 `validation_mode`（`claim_scoped` / `global_structured`）与 `validated_segment_count`；
  `schema_version` 升为 `numeric_claim_trace_v3`。
- **草稿级叙述（`draft_title` / `draft_observation` / `reason_for_status`）不属于主张**，
  没有 evidence 绑定，因此仍然只能用结构化来源核对，不借用同案任何 chunk。
  **D11 已签字**：维持该最严口径，不允许草稿级叙述借用同案 claim 绑定的 chunk。
  理由：一旦允许借用，"每个主张自己负责自己的证据"这条纪律就废了，而那正是 D4 的全部意义。
  实测支持：`41,813,685.32` 只出现在 `normal_explanations[1]`（三条 run 均绑定 P0089），
  三个无绑定叙述段均不含该数字，因此它不是绕过通道。
- **D13 已签字：闸门容差是已知属性，不得改动。**
  匹配容差为 `max(0.005, |来源值| × 0.005)`，`rag_chunk` 来源与结构化来源**同享**该相对容差，
  因此对 41,813,685.32 量级的金额允许约 ±20.9 万偏差才算 traced。
  该值沿用闸门既有口径；收紧或放宽它都等于引入新阈值，违反 D1/D4 铁律，须另行签字。
- `03`/`06` 这类日期串残余 token 仍会记为 unverified，但不满足 `key_unverified` 判据
  （非百分比/年份，且绝对值 <1000），不影响 `passed`；**不得为此新增规则**。
- 历史 `incomplete_numeric_claims` 结论需重新解释，但**不得改写已封存 JSON**。
- 回滚条件：出现任一"凭空数字被 traced"实例。
- 实测（只读重放，零模型调用）：三条封存 run 的 `key_unverified` 由
  `['41,813,685.32']`（`RUN-V7-D8933A6BBDDB` 另有 `'7,156,516.61'`）变为 `[]`，
  均 `traced → RAG-CNINFO_000858_T0_20260430-2025-P0089-C00`；
  同一输入走旧口径（不传 bindings）时仍 `passed=false`。

## 六、`execution_badge.mode` 唯一判定表（轨 C 不得另写一套）

轨 A 已在 `main.py` 按此表产出 `execution_badge`；判定函数唯一实现点是
`backend/app/schemas.py` 的 `execution_badge_for()`（含 `EXECUTION_BADGE_LABELS`），
回放与备用链路径也调用同一个函数。轨 C 的前端应优先读
`run.execution_badge.mode`，字段缺失（旧 run）时才回退到本地判定。

| 输入 | mode | label（逐字） |
| --- | --- | --- |
| `execution_mode == "deterministic_backup"` | `deterministic_backup` | 确定性备用链 |
| `execution_mode in {"cache_replay", "external_cached"}` 或 `cache_hit is true` | `cache_replay` | 已验证历史结果回放 |
| `execution_mode == "external_live"` 且 `cache_hit` 为假 | `external_live` | 本次真实模型运行 |
| 其余（未请求模型、计算预检、模型失败、不可用） | `null` | `null` |

`provider_call_count` 恒为本次运行的真实调用数：回放与备用链为 `0`。
mode 为 `null` 表示"来源无法判定"，前端必须显示"未提供"，
**不得**据此推断任何成功或失败。三态文案的调用数说明由轨 C 按 W12 拼装，
本表只冻结 `mode` 与 `label` 的对应关系。
