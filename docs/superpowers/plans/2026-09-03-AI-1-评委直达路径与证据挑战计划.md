# AI-1：评委直达路径与证据挑战计划

> 计划日期：2026-09-03  
> 负责人：AI-1（网页与真实浏览器验收）  
> 任务类型：未来网页原型改进与演示验收  
> 当前状态：已执行（本机禁用外部模型验收，生产真实模型成功路径仍待真人授权）

## 1. 目标

让一个第一次接触审迹智链的评委，在不阅读长篇说明的情况下完成以下路径：

`打开页面 → 看懂系统交付物 → 进入冻结案例 → 启动一次分析 → 看到一条主张和对应 evidence_id → 一次点击打开原文定位 → 看见人工下一步和失败边界`

本计划只解决首屏、入口和证据展示，不新增审计规则、模型角色、案例和数据源。

## 2. 事实与边界

### 2.1 必须先读取

- 根目录 `AGENTS.md`；
- `index.html`；
- `assets/official-v4/demo-app.js`；
- `assets/official-v4/styles.css`；
- `README_RUN.md`；
- V4 主方案书；
- 当前后端实际提供的案例、任务、结果和导出路由。

### 2.2 允许修改

- 根目录 `index.html`；
- 根目录 `assets/` 下当前网页实际引用的资源；
- 本计划指定的浏览器验收脚本或其输出目录；
- 本计划新增的演示路径记录。

### 2.3 禁止事项

- 不改 `backend/`、发布记录、评估原始记录和 R1 签字；
- 不修改旧网页原型；
- 不硬编码案例结果、模型成功、证据页码或 run_id；
- 不把静态图片当成真实运行证据；
- 不调用付费模型，不部署 Render；
- 不为了“更好看”新增一套与当前主网页并存的页面。

## 3. 执行步骤

### Step 0：建立只读基线

记录当前 HEAD、工作区状态、页面资源版本、浏览器验收入口和后端启动方式。使用当前项目已有的本机演示模式或确定性备用模式，不改变模型配置。

输出：`artifacts/judge-path-20260903/baseline.md`。

### Step 1：绘制当前评委路径

用真实浏览器记录：

- 从首页到工作台需要几次点击；
- 首屏是否直接说明“预审风险备忘录、Top 5 待核查事项、待索取资料清单”；
- 现场样例、技术说明和冻结案例是否混在同一层级；
- 结果区中第一条主张、evidence_id、关键数字、反证状态、人工下一步和原文入口的位置；
- 页面是否出现旧版工作台示意，导致宣传图与实物不一致；
- 失败、降级、RAG 未就绪和任务中断时是否给出一个明确下一步。

输出：`artifacts/judge-path-20260903/current-path.md`，不得只写主观感受，要附选择器、截图文件名或页面状态。

### Step 2：设计“评委直达模式”

只提交小范围设计说明后再改页面，至少写清：

- 评委入口的默认案例；
- 唯一主按钮和次级入口；
- 首屏交付物文案；
- 成功、模型降级、台账不可用三种状态的主提示；
- 手机和平板的折叠顺序；
- 不需要展示的深层技术内容放在哪里。

设计约束：保留项目已有审计证据视觉语义，不引入泛化的宣传口号、紫色渐变或装饰性卡片堆叠。

输出：`artifacts/judge-path-20260903/design-decision.md`。如果设计会改变正式业务文案或方案书口径，先停在计划状态交给 AI-3 和真人确认。

### Step 3：实现最小入口调整

优先实现以下小改动：

1. 评委入口打开后默认显示冻结案例和唯一主操作；
2. 将产品最终交付物写成可直接理解的短句；
3. 将“现场样例”和“技术说明”降为次级入口；
4. 旧版示意图若无法证明与当前页面一致，则删除、替换为已有当前截图，或明确标注为历史示意；
5. 运行结束后，在结果首屏放置一条“30 秒证据挑战”卡。

证据挑战卡必须从当前 `RunResponse` 或同源结果读取：主张、`evidence_id`、关键数字、反证/复核状态、人工下一步和原文定位。若当前接口没有一次点击所需字段，只记录接口缺口，交给 AI-2 评估，不在前端伪造字段。

### Step 4：成功与失败双路径验收

至少实测以下状态：

- 冻结案例成功完成；
- 模型调用失败后的诚实降级；
- RAG 未就绪或台账不可用；
- 刷新后读取已完成结果；
- 运行中断后显示 `interrupted` 并要求显式重跑；
- 结果区折叠、证据抽屉、Agent 抽屉和打印预览。

不得为了获得“成功截图”删除失败状态或复用不同运行的结果。

### Step 5：真实浏览器检查

使用项目现有浏览器验收能力覆盖：

- `1440×1000`；
- `1024×768`；
- `768×1024`；
- `390×844`。

每个视口检查页面溢出、文本裁切、焦点顺序、键盘 Enter/Space/Escape、触控目标、减少动态效果、控制台异常、失败网络请求和关键 API 状态。axe 只作为一项证据，不能代替人工键盘和阅读顺序检查。

输出目录：`artifacts/judge-path-20260903/`，至少包含运行报告、成功和降级截图、控制台/网络摘要、键盘记录和未解决问题表。

## 4. 验收标准

- 评委入口进入工作台最多一次主动点击；
- 首屏能明确说出三类交付物，而不是只罗列 RAG、三 Agent 和 15 案；
- 结果首个视口有一条真实主张和对应 evidence_id；
- 从主张到原文定位不超过一次点击，且 run_id、evidence_id、页码来自同一运行；
- 成功、失败、降级和中断状态均不出现假成功文案；
- 四种视口无横向溢出和关键内容裁切；
- 浏览器控制台无新增未捕获异常，关键请求无未解释 HTTP 错误；
- 任何无法用当前后端事实支持的 UI 想法都登记为“待后端补证”，不得自行填充。

## 5. 交接内容

交给 AI-2：接口字段缺口、失败状态下观察到的 API 行为、可能影响发布门禁的前端问题。  
交给 AI-3：最终交付物文案、演示路径、截图编号和可用于答辩的“主张—证据—人工下一步”案例。  
交给真人：需要决定的正式文案、是否删除旧图、演示默认案例和视频镜头。

## 6. 停止条件

遇到以下情况立即停止扩展：

- 需要修改后端 schema 才能展示字段；
- 需要新增案例、RAG 来源或模型角色；
- 需要付费模型调用才能取得截图；
- 现有结果的证据定位无法确认；
- 页面改动会改变方案书中的正式事实。

## 7. 2026-09-03 执行结果

- 首屏主按钮已改为一次点击直达工作台，默认使用首个精选冻结案例；显式 `?case=` 仍可选择其他登记案例。
- 首屏和工作台已明确三类交付物：预审风险备忘录、Top 5 待核查事项、待索取资料清单。
- 技术说明与现场样例已收进“次级入口”，旧版工作台截图已从定位页删除。
- 结果首屏新增“30 秒证据挑战”，从同一运行读取主张、`evidence_id`、关键数字、反证/复核状态、人工下一步、`document_id` 与 `pdf_page`；字段不足时明确失败关闭。
- 四视口专用评委路径验收、四视口既有 axe/键盘/抽屉/打印/下载验收和仓库全量测试均通过。证据见 `artifacts/judge-path-20260903/`。
- 本次启动参数明确关闭外部模型和 provider probe，实际结果为确定性备用降级路径，未把它写成真实模型成功；生产真实模型成功路径、真实实例中断重启和生产发布门禁不在 AI-1 本机验收结论内。
