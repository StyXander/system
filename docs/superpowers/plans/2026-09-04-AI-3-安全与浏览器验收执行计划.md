## 2. 验收范围与通过条件

### 2.1 安全边界

- 页面、健康检查、公开状态、内部状态和静态脚本均返回预期安全响应头；CSP 不含 `unsafe-inline` 或 `unsafe-eval`。
- `/api/status` 只返回公开白名单投影，不泄露开发路径、缓存、内部目录、模型密钥或评估底稿。
- `/api/internal/status` 在默认配置下拒绝访问；只有显式受控的 loopback 开关才能打开。
- 恶意 Origin 不获得 CORS 放行；常见路径穿越请求返回 404 或明确阻断。
- 工作区和评委 ZIP 均完成密钥/令牌扫描；评委 ZIP 不含 `.env`、`.git`、虚拟环境、PDF 全文或阻断项。

### 2.2 真实浏览器

使用真实 Chromium 浏览器在 `1440x1000`、`1024x768`、`768x1024` 和 `390x844` 四个视口运行完整路径：进入工作台、运行确定性备用演示、查看结果、展开证据抽屉和 Agent 抽屉、打印预览、下载 JSON/CSV、键盘 Enter/Escape/Space 操作。

每个视口必须同时满足：

- 主入口一次点击进入工作台；
- 30 秒证据挑战的主张、run_id、证据编号、关键数字、复核状态和人工下一步齐全，且来自同一 run；
- 原文来源响应 200；
- 无重复 id、无无名控件、无横向溢出、无控制台/页面/请求/HTTP 错误；
- axe 通过同源虚拟脚本注入并真实执行，所有覆盖状态 0 violations；
- 抽屉键盘行为和焦点回归通过，打印展开和下载通过。
